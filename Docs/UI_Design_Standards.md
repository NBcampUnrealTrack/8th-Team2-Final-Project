# ProjectM UI 디자인 표준

전체 화면의 시각 언어와 공통 컴포넌트 기준

버전 0.1  |  2026년 10월 14일  |  디자인 담당자와 AI 작업자 공통 참조

## 1. 문서 개요

ProjectM의 모든 UI는 JRPG의 절제된 장식성과 현대적인 플로팅 카드 구성을 공유한다. 네이비는 화면의 중심을 잡고, 밝은 아이보리는 정보를 담으며, 크림과 저채도 골드는 선택과 상징을 드러낸다. 화면의 목적에 따라 구성과 색 면적은 달라져도 같은 부품의 형태와 상태 표현은 일관되게 유지한다.

### 문서가 정하는 것

색의 역할, 글자 위계, 여백, 패널과 프레임의 형태, 버튼과 입력 상태, 아이콘과 심볼, 배경 장식, 화면별 표현 강도, 에셋 마감과 디자인 검수 기준을 정한다. 위젯 상속·화면 스택·데이터 흐름은 이 문서의 범위에 포함하지 않는다.

### 기준의 상태

| 표시 | 의미 |
| --- | --- |
| 공통 고정 | 이미 합의한 톤앤매너와 제작 원칙. 화면별 작업에서 유지한다. |
| 표준 제안 | 이번 문서에서 구체화한 형태·HEX·치수·시간. 대표 화면 검토 후 공통값으로 확정한다. |
| 화면 예외 | 화면의 목적에 필요한 차이. 적용 영역과 이유를 기록하고 공통 부품의 규칙은 연결한다. |

### 판단 우선순위

가독성과 상태 구분 → 정보 위계와 조작 대상 → 컴포넌트 통일 → 세계관의 분위기 → 작은 마감 순으로 판단한다. 장식은 화면의 특징을 만들되, 수치와 선택 상태를 가리지 않는다.

## 2. 색상과 역할

공통 고정은 네이비·아이보리·크림·저채도 골드의 조합이다. 아래 HEX는 기존 작업용 제안값을 이어받은 시작값이며, 팀의 확정 팔레트로 일괄 교체할 수 있다.

| Mist Gray | #DCE2E3 | 보조 면, 카드 사이 배경, 저대비 장식 |

| Muted Red | #8E3D49 | 오류, 삭제 등 손실을 수반하는 동작 |
| 보조 텍스트 | #52616A | 밝은 면 위 부가 설명과 라벨 |

### 색을 배분하는 규칙

통합 메뉴는 네이비 내비게이션과 아이보리 정보 카드를 기본으로 한다. 회청색은 차가운 하늘색으로 보이지 않도록 낮은 채도를 유지한다. 크림 선택면이 묻히는 밝은 영역에서는 네이비 선택면과 크림 글자를 사용한다.

골드는 화면 전체의 틀을 두르는 색으로 남용하지 않는다. 밝은 면 위 작은 본문을 골드로 쓰지 않고 네이비로 읽히게 한다. 흰색에 가까운 큰 면, 순검정의 큰 면, 넓은 하늘색 선택면은 피한다.

HP·SP·속성·등급 등 기존 의미색은 유지한다. 성공·오류도 문구나 아이콘을 함께 사용한다. 브라운은 상점·퀘스트의 소재 표현에 제한하며 공통 버튼 색을 화면마다 바꾸지 않는다.

## 3. 글자와 간격

공통 고정은 기능명과 게임 데이터 중심의 텍스트 사용이다. 장식용 영문 부제·슬로건·모토를 추가하지 않는다. 아래 수치는 1920 × 1080 화면에서 시작하는 표준 제안이다.

| 역할 | 시작 크기 | 표현 규칙 |
| --- | --- | --- |
| 화면 제목 | 30–32 px | 현재 화면을 식별한다. 제목을 장식처럼 반복하지 않는다. |
| 섹션 제목 | 23–24 px | 중간 굵기. 본문보다 여백으로 구분한다. |
| 본문과 조작명 | 20–22 px | 가독성 높은 한글 고딕 계열. 얇은 획을 피한다. |
| 보조 정보 | 17–18 px | 작게 줄이기 전에 표현을 간결하게 정리한다. |
| 핵심 수치 | 24–28 px | 레벨·주요 능력치 등 필요한 값에만 적용한다. |
| 긴 설명문 | 20 px 전후 | 줄간격 1.4–1.5배. 반복 강조와 외곽선을 줄인다. |

### 서체와 정렬

본문과 조작명은 공통 서체 한 계열로 통일한다. 세리프나 장식 서체는 로고와 제한된 제목에만 허용한다. 게임 본문 서체의 최종 파일과 굵기는 별도로 등록한다. 픽셀 캐릭터에 맞추기 위해 작은 본문까지 픽셀 서체로 바꾸지 않는다.

항목명은 왼쪽, 비교하는 수치는 오른쪽에 정렬한다. 단위와 자릿수 폭을 일정하게 유지하고 가능한 경우 고정폭 숫자를 사용한다. 닉네임·클래스·레벨·경험치의 중복 강조를 없애되 필요한 데이터는 남긴다.

### 공통 간격

| 대상 | 표준 제안 | 적용 |
| --- | --- | --- |
| 간격 단위 | 4 px 보정 / 8 px 기본 | 세부 정렬은 4, 일반 여백은 8의 배수 |
| 카드 내부 | 24 px | 정보가 많은 작은 카드만 16 px |
| 카드 사이 | 16–24 px | 같은 묶음보다 서로 다른 묶음의 간격을 크게 |
| 조작 높이 | 48 px 기본 / 40 px 소형 | 시각 높이와 조작 영역을 함께 점검 |
| 아이콘과 글자 | 8–12 px | 아이콘의 보이는 외곽을 기준으로 보정 |

긴 이름은 정해진 폭에서 줄바꿈 또는 말줄임으로 처리하고 전체 이름을 확인할 수 있게 한다. 설명문은 임의 축소 대신 줄바꿈·높이 조정·스크롤을 사용한다. 작은 해상도에서도 중요한 본문을 먼저 보호한다.

## 4. 면과 프레임

공통 고정은 밝은 정보면과 네이비 보조면의 대비, 얇고 연속된 테두리, 얕은 깊이감이다. 평면적인 인상을 유지하면서 여백과 약한 그림자로 카드를 구분한다.

| 요소 | 표준 제안 | 일관성 기준 |
| --- | --- | --- |
| 일반 카드 | 45도 사선 / 절삭 8 px | 좌우·상하 모서리 구조를 동일하게 연결 |
| 버튼과 입력창 | 45도 사선 / 절삭 4 px | 카드와 같은 각도, 더 작은 절삭량 |
| 외곽선 | 1 px 기본 / 강조 2 px | 같은 컴포넌트 안에서 굵기 일정 |
| 이중 프레임 | 간격 4 px | 대표 창과 선택에 제한, 모든 카드에 반복 금지 |
| 그림자 | 아래 4 px / 번짐 12 px / 12–18% | 짙은 네이비 계열, 카드 면보다 약하게 |
| 정보면 불투명도 | 92–100% | 수치와 긴 본문의 배경을 안정화 |
| 게임 위 패널 | 82–92%부터 검토 | 밝은 지면·초록 지면 위에서 색과 글자 확인 |

### 제목부와 카드의 관계

일반 카드의 제목은 카드 내부에 두고 패딩과 얇은 구분선으로 본문을 나눈다. 돌출 제목 바나 휘장은 대표 창의 특징으로 필요한 경우에만 사용한다. 모든 정보 묶음을 독립된 상자로 쪼개지 않는다.

모서리 절삭형은 이번 공통안의 제안이다. 원형 미니맵·게이지와 전용 아이콘 버튼은 별도 유형으로 관리한다. 한 유형 안에서 둥근 모서리·사선·장식 코너를 임의 혼합하지 않는다. 내부 질감과 하이라이트는 외곽선을 넘지 않는다.

## 5. 버튼과 상태 표현

선택은 현재 값이고, 포커스는 키보드·패드 조작의 대상이며, 호버는 포인터가 올라간 상태다. 서로 겹칠 수 있으므로 같은 효과 하나로 표현하지 않는다.

| 상태 | 면과 글자 | 형태와 효과 |
| --- | --- | --- |
| 기본 | 현재 배경에 맞는 네이비 또는 아이보리 | 얇은 테두리와 일관된 여백 |
| 호버 | 면을 한 단계 밝히되 글자 대비 유지 | 내부 명도 변화, 번지는 빛은 사용하지 않음 |
| 포커스 | 현재 선택색을 그대로 보존 | 바깥 2 px 선과 2–4 px 간격, 주변 잘림 금지 |
| 눌림 | 면을 한 단계 어둡게 | 얕은 그림자 감소, 텍스트 위치는 고정 |
| 선택 | 네이비 위 크림 / 밝은 면 위 네이비 | 작은 골드 마커 또는 선으로 지속 표시 |
| 비활성 | 채도와 면 대비를 낮춤 | 글자 전체를 흐리지 않음. 불가 사유 확인 가능 |

### 동작의 중요도

주요 실행은 저채도 골드 면과 네이비 글자를 시작안으로 사용한다. 보조 동작은 주변에 맞는 중립 면으로 둔다. 같은 의사결정 묶음에서 가장 중요한 동작 하나를 우선 강조한다. 선택된 탭은 실행 버튼과 구분해 표현한다.

빨강은 삭제·초기화·진행 손실 등 결과에 위험이 있을 때 사용한다. 닫기·취소·안전한 화면 이동까지 일괄 빨강으로 만들지 않는다. 닫기 버튼은 동일 종류의 창에서 배경 형태와 X의 획 두께를 공유한다.

상태 우선순위는 비활성 여부 → 선택면 → 눌림 또는 호버의 면 변화 → 포커스 외곽선이다. 포커스는 선택면 위에서도 읽혀야 한다. 비활성 항목이 포커스를 받는 기존 동작이라면 불가 상태와 포커스를 함께 표시한다.

## 6. 입력과 선택 컴포넌트

버튼에서 정한 면색·모서리·외곽선 규칙을 입력창과 옵션 조작에도 적용한다. 사용자가 바꾼 값과 입력 결과가 장식보다 먼저 읽혀야 한다.

| 컴포넌트 | 기본 표현 | 선택 또는 조작 상태 |
| --- | --- | --- |
| 텍스트 입력 | 패널과 같은 계열의 면, 독립된 라벨 | 포커스 외곽선, 입력값은 본문 대비 유지 |
| 드롭다운 | 입력창과 같은 높이, 공통 화살표 | 열린 목록·현재 값·호버 항목을 별도로 표시 |
| 토글 | 명확한 트랙과 손잡이 | 손잡이 위치와 켜짐·꺼짐 표현을 함께 사용 |
| 체크와 단일 선택 | 동일한 상자·원 크기와 내부 여백 | 체크 표식 또는 채움으로 상태 구분 |
| 슬라이더 | 값 트랙·남은 트랙·손잡이 구분 | 현재 값과 조작 초점이 확인되게 유지 |
| 탭과 필터 | 주 분류는 면, 하위 분류는 작은 탭·밑줄 | 탭 간 위계와 현재 분류를 동시에 읽히게 |
| 스크롤바 | 낮은 대비의 레일, 더 선명한 손잡이 | 포커스·호버 시 손잡이 선명도 증가 |
| 키캡 | 공통 네이비 또는 아이보리의 작은 프레임 | 입력 기호를 중앙 배치, 아이콘과 크기 조화 |

### 수치 시작값

일반 입력 높이 48 px, 좌우 패딩 16 px, 화살표 영역 32 px를 제안한다. 스크롤 손잡이의 보이는 폭은 6–8 px부터 검토하고 조작 영역은 더 넓게 둔다. 슬라이더 손잡이는 지름 18–20 px부터 검토한다. 숫자는 실제 입력 방식과 화면 배율에 맞춰 확정한다.

### 입력 결과와 대기 상태

오류는 입력창의 테두리와 가까운 설명으로 표시한다. 성공은 필요한 결과 문구와 표식으로 알리고 전체 패널을 초록색으로 바꾸지 않는다. 입력 예시 문구를 라벨 대신 쓰지 않는다.

처리 중에는 해당 조작 영역에 진행 표시를 두고 폭과 높이를 유지한다. 빈 상태·불러오는 상태·오류 상태를 동일한 빈 카드로 처리하지 않는다. 안내는 실제 존재하는 다음 행동만 제시한다.

### 툴팁과 보조 설명

툴팁도 같은 패널 계열과 본문 서체를 사용한다. 설명은 한 대상에 연결되게 배치하고 다른 조작 영역을 가리지 않는다. 긴 툴팁은 문장 구조와 줄간격을 정리하며 글자를 과도하게 줄이지 않는다.

## 7. 아이콘과 대표 심볼

메뉴 아이콘은 빠른 식별, 장비·스킬 이미지는 콘텐츠 구분, 대표 심볼은 세계관의 정체성을 담당한다. 세 범주를 같은 디테일 수준으로 맞추지 않는다.

| 범주 | 조형 기준 | 색과 배경 |
| --- | --- | --- |
| 메뉴와 조작 | 단순한 실루엣, 필요한 내부선만 사용 | 네이비 또는 크림 단색 중심 |
| 장비와 스킬 | 대상을 구분할 묘사는 유지 | 개별 컬러 허용, 슬롯 프레임과 배경 통일 |
| 대표 심볼 | 승인된 원본의 비례와 핵심 형태 유지 | 제목·상징 장식·워터마크의 용도에 맞게 변형 |

### 메뉴 아이콘의 공통 수치

32 px 캔버스에 보이는 도형 22–24 px, 기본 획 2 px를 시작안으로 제안한다. 48 px 캔버스는 비례를 유지하되 작은 구멍과 선이 뭉개지지 않게 보정한다. 정사각형 바운딩 박스만 맞추지 말고 실제 면적과 무게중심을 나란히 비교한다.

장비는 갑옷이나 장비를 나타내는 형태, 인벤토리는 가방으로 구분한다. 외모는 얼굴 옆모습과 이목구비를 간결하게 쓰고, 의미 없는 종족 특징을 추가하지 않는다. 눈 뜸·눈 감음은 같은 캔버스·비례·획으로 제작한다.

### 대표 심볼의 세 가지 용도

| 용도 | 시작 크기 | 다듬는 방식 |
| --- | --- | --- |
| 큰 장식 | 128 px 이상 | 핵심 내부 구조를 살리되 잔선을 제한 |
| 제목 아이콘 | 24–48 px | 작은 크기에서 사라지는 선을 제거한 전용 원본 |
| 배경 워터마크 | 영역에 맞게 확대 | 대비를 낮추고 잘림·겹침을 통제 |

임시 또는 최종 심볼 원본을 첨부해 사용한다. 비슷한 나침반·별을 AI가 추정해 다시 그리거나 대체하지 않는다. 원본이 없으면 교체 위치와 필요한 파일을 명시하고 심볼 확정 완료로 보고하지 않는다.

### 버튼 프레임과 예외

HUD 아이콘 배경은 승인된 공통 프레임 한 종류를 공유한다. 원형·팔각형 중 최종 형태는 대표 보드에서 확정하며 과거 안을 임의로 섞지 않는다. 퀘스트의 주황색 느낌표처럼 이미 의미가 정해진 예외는 유지한다.

## 8. 배경 장식과 캐릭터 연출

장식의 강도는 정보의 역할에 따라 조절한다. 읽는 영역을 정리하면서 캐릭터 전시 공간과 대표 심볼의 존재감은 남긴다. 화면 전체를 일괄적으로 흐리게 만들지 않는다.

| 영역 | 시각적 역할 | 표현 기준 |
| --- | --- | --- |
| 정보 본문 뒤 | 글자와 수치의 안정된 배경 | 잔무늬 최소화, 카드 면의 불투명도로 보호 |
| 캐릭터 전시 | 캐릭터가 화면의 주인공임을 전달 | 실루엣·바닥 반사는 인지 가능하게 유지 |
| 화면 가장자리 | JRPG의 분위기와 프레임 연결 | 절제된 추상 문양, 콘텐츠와 분리 |
| 대표 심볼 위치 | 해당 화면의 상징적 중심 | 중복 반복을 줄이고 한 곳에 우선순위 부여 |
| 선택 대상 주변 | 현재 조작과 상태 안내 | 선·마커 중심, 주변 장식과 다른 형태 |

### 표현 강도의 시작점

밝은 배경 위 워터마크는 낮은 대비의 색으로 4–8% 불투명도부터, 전시 공간의 실루엣은 12–20%부터 검토한다. 이는 최종 수치가 아니다. 원본 색과 게임 배경에 따라 결과가 달라지므로 합성된 화면의 가독성과 인지성을 기준으로 결정한다.

새로운 문양은 선의 두께·곡률·대칭축을 정리하고 승인된 심볼과 형태를 연결한다. 기존 나침반·궤도·나뭇잎은 필요한 부분을 남기거나 재구성할 수 있다. 동일 문양을 헤더·카드·캐릭터 뒤에 같은 강도로 반복하지 않는다.

### 캐릭터와 소재의 경계

픽셀 캐릭터 원본의 비율·색·외형을 보존한다. 실루엣은 캐릭터에 연결되는 형태로 두고, 바닥 반사는 발밑에서 자연스럽게 약해지게 한다. 실사적인 천·금속·가죽 질감이 픽셀 캐릭터보다 강하게 보이지 않게 한다.

성·도시·나무·깃발을 빈 공간을 채우기 위한 장식으로 임의 추가하지 않는다. 기존 게임 배경이나 승인된 화면 고유 소재는 유지할 수 있다. 나이아의 해방을 새로 표현할 때도 사슬·날개·자물쇠·새장 같은 직접적 기호를 자동으로 덧붙이지 않는다.

### 움직임의 기준

표준 제안은 호버·포커스 80–120 ms, 일반 창의 등장·퇴장 150–200 ms다. 짧은 페이드와 작은 이동으로 시작하고 조작 영역의 위치가 흔들리지 않게 한다. 반복 블룸·펄스·과장된 튕김은 기본 상태에 넣지 않는다. 시간에 민감한 판정 표시는 지연 없이 읽혀야 한다.

## 9. 전체 화면과 통합 메뉴 적용

공통 부품의 색과 조형은 공유하되, 각 화면의 내용량과 시각적 중심은 달리 설계한다. 아래 항목은 디자인 적용 기준이며 화면 좌표나 위젯 구조를 고정하지 않는다.

| 화면 | 주요 표현 | 먼저 확인할 대상 |
| --- | --- | --- |
| 타이틀과 로그인 | 세계관 연출과 절제된 네이비 입력부 | 로고보다 튀지 않는 조작부, 입력값 대비 |
| 로딩 | 승인된 배경과 간결한 진행 표시 | 진행 상태와 안내의 가독성 |
| 캐릭터 선택 | 캐릭터 카드와 선택 프레임 중심 | 선택 카드·생성 카드·빈 슬롯의 강도 차이 |
| 캐릭터 생성 | 밝은 편집면과 네이비 선택 상태 | 종족 설명, 현재 외형 선택값, 이름 결과 |
| 통합 메뉴 | 네이비 내비게이션과 밝은 정보 카드 | 선택 메뉴, 화면 제목, 주요 정보의 우선순위 |
| 캐릭터 정보 | 캐릭터 전시와 정보 카드의 균형 | 식별 정보·성장·보조 정보의 읽기 순서 |

### 통합 메뉴 공통 부품

메뉴 버튼, 헤더, 닫기 버튼, 카드 프레임, 탭, 스크롤바는 같은 유형끼리 형태와 상태를 공유한다. 좌측 메뉴의 선택은 크림 면과 네이비 글자를 기본으로 하며, 선택 마커와 포커스 표시를 분리한다. 메뉴가 늘어날 때 글자를 줄이거나 간격을 화면마다 임의 축소하지 않는다.

### 캐릭터 정보 화면의 기준 역할

대표 화면에서는 메뉴 버튼 조형, 제목부, 카드 내부 정보 묶음, 전시 공간을 함께 다듬는다. 카드 밖으로 돌출된 제목 바를 반드시 유지할 필요는 없다. 닉네임·클래스·레벨은 한 곳을 중심으로 읽히게 하고 경험치는 별도 성장 정보로 구분한다.

캐릭터 전시의 실루엣과 반사를 살린 상태에서 정보 카드의 크기·간격·여백을 조정한다. 헤더의 대표 아이콘은 승인 원본을 사용한다. 장비·인벤토리·스탯·나이아는 같은 부품을 활용하되 동일 카드 배열을 복제하지 않는다.

### 허용하는 화면별 차이

타이틀의 장식 밀도, 캐릭터 전시 공간의 크기, 카드의 개수와 비율, 콘텐츠 배경의 색 면적은 달라질 수 있다. 공통 색의 역할·모서리 각도·획 두께·본문 서체·상태 의미는 함께 유지한다.

## 10. HUD와 오버레이 적용

플레이 중 UI는 게임 장면 위에서 읽혀야 한다. 패널의 색이 지면에 물들지 않도록 면과 글자를 따로 조절하고, 본문을 보호할 만큼의 불투명도를 확보한다.

| 화면 | 공통 스타일 적용 | 화면 고유 기준 |
| --- | --- | --- |
| 필드 HUD | 네이비 바탕, 크림 아이콘, 얇은 프레임 | 지도·퀘스트·자원 표시의 식별성 우선 |
| 채팅 | 네이비 반투명 읽기 면과 공통 키캡 | 채팅 본문·입력창·탭의 강도 구분 |
| 전투 | 네이비 명령부와 기존 자원 의미색 | 행동·대상·판정 정보를 장식보다 강조 |
| NPC 대화 | 안정된 본문 면과 절제된 이름부 | 긴 문장 몰입, 직업·이름부의 높이 연결 |
| 퀘스트 | 저채도 아이보리와 간결한 스크롤 소재 | 목록과 상세의 위계, 저대비 문양 |
| 상점 | 아이보리·네이비, 제한된 브라운 | 상품·가격·선택·거래 결과의 식별성 |
| 다른 유저 정보 | 통합 메뉴의 카드와 아이콘 재사용 | 조회용 정보 위계와 제한된 동작 |
| 설정과 키 설정 | 공통 입력·토글·슬라이더와 카드 | 현재 값, 변경 상태, 포커스를 명확히 |
| 확인 팝업 | 간결한 제목부와 얇은 연속 프레임 | 행동 결과와 주요 버튼을 먼저 읽히게 |
| 결과 화면 | 밝은 정보 카드와 제한된 골드 강조 | 결과·보상·다음 행동의 위계 |

### 공통 배치를 새로 결정하지 않는 항목

미니맵의 좌우 위치, 메뉴의 배열 방식, 창을 여는 경로는 최신 승인 화면을 따른다. 디자인 표준을 적용한다는 이유로 옛 시안의 위치로 되돌리지 않는다. 조작 기능이나 데이터가 필요한 디자인은 화면별 작업 범위에서 확인한다.

### 대화와 팝업의 특별 기준

NPC 초상화는 확정된 화면의 사용 여부를 따른다. 초상화가 없어도 본문 면과 이름부가 완성된 형태로 보이게 한다. 확인 팝업에는 불필요한 장식 문구를 추가하지 않고, 제목 심볼과 워터마크의 조형을 맞춘다. 작은 창에 큰 창의 장식을 그대로 축소해 넣지 않는다.

## 11. RPG 정보와 상태 구분

게임 정보의 상태는 색·형태·표식 중 두 가지 이상을 조합해 구분한다. 선택·보유·장착·획득 가능을 같은 골드 테두리 하나로 처리하지 않는다.

| 대상 | 유지할 내용 | 디자인 기준 |
| --- | --- | --- |
| 장비 슬롯 | 부위·장착·선택·등급 | 빈 부위 실루엣은 저대비, 선택은 별도 외곽선 |
| 인벤토리 | 분류·수량·선택·비활성 | 프레임은 공통화, 수량 표시는 같은 위치와 대비 |
| 스탯 | 항목·값·비교 또는 변동 | 라벨은 왼쪽, 숫자는 오른쪽, 단위를 같은 규칙으로 |
| 나이아 | 보관·선택·편성·참여 상태 | 각 상태 표식 분리, 빈 능력치 칸만 늘어놓지 않음 |
| 특성 트리 | 노드 상태·연결·현재 선택 | 배경 대비를 줄이고 진행 경로와 대상 노드를 강조 |

### 특성 노드 상태

| 상태 | 아이콘과 프레임 | 연결 경로 |
| --- | --- | --- |
| 획득 완료 | 골드 프레임과 완료 표식 | 지나온 경로를 선명하게 |
| 획득 가능 | 선명한 아이콘과 작은 가능 표식 | 해당 노드로 이어지는 연결을 읽히게 |
| 잠김 | 낮은 채도와 잠김 표식 | 약한 연결선, 필요한 조건은 설명으로 |
| 현재 선택 | 외곽 이중선 또는 선택 마커 | 획득 여부를 덮지 않는 독립 표시 |

### 전투와 자원 표시

상태바는 대상과의 관계가 보이게 일정한 간격·이름·표식으로 연결한다. HP·SP의 의미색은 보존하고 어두운 바탕, 끝단, 수치 스타일을 통일한다. 타이밍 게이지의 판정 구간과 움직이는 포인터는 색뿐 아니라 형태도 다르게 한다.

전투 채팅의 시각적 무게가 행동 메뉴를 압도하지 않도록 밀도와 면적을 검토한다. 자동 접힘 같은 동작 변경은 별도 기능 제안으로 구분한다. 나침반 등 장식은 정보와 캐릭터를 가리지 않는 범위에 둔다.

### 빈 상태와 긴 데이터

빈 슬롯과 로딩은 구분한다. 실제로 비어 있을 때만 이유와 가능한 다음 행동을 짧게 안내한다. 최대 자릿수, 긴 이름, 여러 줄 설명에서도 슬롯·카드·선택 표시가 겹치지 않아야 한다.

## 12. 에셋 제작과 마감

공통 고정은 독립된 에셋과 투명 배경, 연속된 테두리다. 설명용 완성 시안에는 텍스트와 버튼을 합성할 수 있지만, 구현용 기본 패널은 순수한 면과 프레임만 갖는다.

| 분리 대상 | 포함하는 것 | 포함하지 않는 것 |
| --- | --- | --- |
| 기본 패널 | 패널 바탕과 외곽 프레임 | 글자·아이콘·버튼·구분선·워터마크 |
| 버튼 배경 | 버튼 면과 테두리 | 기능명·아이콘·키 표시 |
| 아이콘 | 아이콘의 도형 | 버튼 배경과 주변 패널 |
| 구분선 | 독립된 선과 필요한 끝단 | 패널 면과 제목 |
| 심볼과 워터마크 | 승인된 심볼의 용도별 버전 | 패널 바탕과 텍스트 |
| 상태 효과 | 선택·포커스·호버용 표시 | 기본 패널에 미리 합성된 발광 |
| 그림자와 반사 | 필요한 깊이감 또는 연출 | 본문과 조작 요소 |

### 알파와 테두리

에셋 외부는 알파 투명으로 제작한다. 투명 출력이 불가능한 경우에만 순백 배경 대체를 명시한다. 체크무늬를 픽셀에 그려 넣지 않는다. 투명 배경과 패널 자체의 반투명도를 서로 혼동하지 않는다.

금·크림·네이비 테두리는 모든 구간에서 같은 구조로 끊김 없이 이어져야 한다. 내부 그라데이션·질감·빛이 테두리를 덮지 않게 한다. 투명 가장자리를 밝고 어두운 배경에 합성해 흰 테두리 자국과 잘린 그림자를 확인한다.

### 외곽선 연결과 중복선 검수

외곽 프레임과 메뉴·헤더·카드가 맞닿는 부분은 개별 에셋이 아니라 조립된 화면을 기준으로 검수한다. 직선과 사선 모서리의 접합점, 선의 굵기와 간격을 맞추고 끊김·엇갈림·돌출·겹침이 없어야 한다. 패널을 화면 가장자리에 붙이거나 확대·축소한 뒤에도 같은 기준을 적용한다.

하나의 경계를 부모 프레임과 자식 패널이 각각 그려 의도치 않은 이중선, 가까운 평행선, 교차선 또는 유난히 굵고 진한 구간이 생기지 않게 한다. 공유 경계는 한쪽에서만 그리거나 접합 구간의 중복선을 제거한다. 바깥 프레임이 메뉴 안쪽으로 관통하거나 패널 경계에 불필요한 잔여선이 남는 것도 수정 대상이다.

의도된 이중 프레임은 장식 위계가 필요한 곳에만 사용하고, 두 선의 간격·굵기·모서리 연결을 일관되게 유지한다. 겹친 에셋 때문에 우연히 생긴 두 줄을 디자인된 이중 프레임으로 간주하지 않는다. 원본 확대뿐 아니라 실제 실행 화면의 표시 크기와 서로 다른 화면 비율에서 전체 외곽 및 접합부를 확인한 뒤 완료로 보고한다.

### 크기 변화와 납품

크기가 바뀌는 프레임은 고정할 모서리와 늘릴 중앙 구간을 구분한다. 긴 패널에서도 모서리 각도와 선 두께가 유지되어야 한다. 심볼과 그림자는 프레임 확대에 따라 무작정 늘리지 않는다.

납품에는 원본 크기, 권장 표시 크기, 투명 여백, 기준점, 늘림 가능 구간, 색상 역할, 상태 이름을 함께 기록한다. 동일 유형은 같은 캔버스와 정렬 기준을 사용한다. 원본과 실제 적용 크기의 미리보기를 모두 확인한다.

예시 이름은 Panel_Info_Light, Button_Primary, Icon_Equipment, Divider_Section, Symbol_Header, State_Focus처럼 역할이 드러나게 정한다. 명명 방식은 프로젝트의 기존 규칙이 있으면 그 규칙을 따른다.

## 13. 디자인 검수 기준

완료는 수정한 위젯의 개수로 판단하지 않는다. 대표 화면과 공통 컴포넌트의 실제 인상을 비교해 형태·구성·위계·상태가 의도대로 달라졌는지 확인한다.

| 검수 축 | 통과 기준 |
| --- | --- |
| 전체 인상 | 같은 게임의 팔레트와 조형으로 보이며 화면 목적의 차이가 남아 있음 |
| 구성과 위계 | 제목·주요 정보·보조 정보·조작 대상의 순서가 구분됨 |
| 조형 | 메뉴·헤더·카드·프레임의 필요한 형태 개선이 실제로 반영됨 |
| 글자 | 밝은 면·어두운 면·반투명 면에서 본문과 비활성 정보가 읽힘 |
| 상태 | 선택·호버·포커스·눌림·비활성 및 겹치는 상태가 구분됨 |
| 장식 | 캐릭터 전시의 특징은 남고 수치 뒤 무늬는 정보를 방해하지 않음 |
| 마감 | 끊긴 테두리·잘린 모서리·뭉개진 문양·알파 가장자리 자국이 없음 |
| 데이터 | 긴 이름·최대 수치·빈 상태·오류에서 겹침과 잘림이 없음 |

### 비교 화면 준비

수정 전·목표 시안·수정 후를 같은 해상도, 배율, 데이터 상태로 비교한다. 전체 화면과 메뉴·카드·아이콘의 실제 크기 확대를 함께 확인한다. 구현이 포함된 작업은 시안 이미지뿐 아니라 실행 화면을 사용한다.

1920 × 1080을 기본 비교 기준으로 사용하고 실제 지원하는 작은 해상도에서도 본문과 포커스를 확인한다. HUD와 대화창은 밝은 배경·어두운 배경·초록 지면 위에서 검토한다. 색상 견본만으로 반투명 UI를 승인하지 않는다.

### 개선의 근거를 남기는 방식

각 변경은 “기존 문제 → 적용한 형태나 배치 → 화면에서 확인한 결과”로 짧게 기록한다. 색상 조정과 정렬만으로 완료하지 않고, 작업에서 요구한 메뉴 조형·제목부·카드 구성·아이콘 교체가 실제 반영됐는지 설명한다.

결과 보고는 디자인 시안 완료, 에셋 제작 완료, 실제 적용 완료, 실행 검수 완료를 구분한다. 미완료 항목과 필요한 원본·도구가 있으면 함께 남긴다. 기능 추가 제안은 디자인 완료 사항에 섞지 않는다.

## 14. AI 작업에 적용하는 기준

이 문서는 모든 AI가 공유하는 상위 디자인 기준이다. 작업마다 대상 화면과 원하는 시각적 변경을 덧붙인다. 문서만 전달하고 최종 모습과 변화량을 AI의 추정에 맡기지 않는다.

### 함께 전달할 자료

이 문서의 같은 버전, 현재 화면, 승인된 공통 컴포넌트 보드, 대표 심볼 원본, 해당 화면의 목표 시안 또는 구체적인 변경 항목을 전달한다. 이미지는 수정 대상·공통 스타일·화면 목표의 역할을 구분해 첨부한다.

### 공통 작업 지시문

> 첨부한 ProjectM UI 디자인 표준을 적용하라. 게임 기능·실제 데이터·입력 동작·픽셀 캐릭터 원본은 유지한다. 시각 디자인은 필요한 범위에서 재설계하라. 메뉴 버튼 형태, 헤더, 카드 내부 구성, 여백, 아이콘, 프레임, 장식 배치는 작업 대상이다. 현재 좌표와 형태를 모두 고정하라는 의미로 해석하지 않는다.

> 먼저 이번 화면의 목표와 구체적인 변경 항목을 정하고, 그 항목이 보이는 완성 시안을 제시하라. 색과 불투명도 외에 형태·구성·정보 위계의 변경을 확인할 수 있게 하라. 디자인용 문구나 임의의 세계관 오브젝트로 변화량을 만들지 않는다. 승인된 시안과 공통 규칙을 기준으로 에셋 제작과 실제 적용을 진행하라.

> 시안·에셋·실제 적용·실행 검수의 완료 여부를 구분하고 수정 전후를 같은 조건으로 비교하라. 현재 도구로 만들거나 교체할 수 없는 항목은 구체적으로 밝히고 대체 가능한 범위를 제시하라. 원본이 없는 대표 심볼은 추정 제작하지 않는다.

### 공통안 확정 순서

캐릭터 정보 화면과 컴포넌트 보드에서 면·버튼·헤더·선택 상태를 확인한다. 정보 밀도가 높은 인벤토리에서 가독성과 슬롯 반복을 검토하고, HUD에서 반투명 면과 작은 아이콘을 확인한다. 통과한 공통 부품을 다른 화면에 적용한다.

### 다음 버전에서 확정할 항목

| 항목 | 확정할 내용 |
| --- | --- |
| 팔레트와 서체 | 최종 HEX, 본문·제목 서체 파일과 굵기 |
| 공통 조형 | 사선 모서리 안, HUD 아이콘 버튼 프레임의 최종 형태 |
| 대표 심볼 | 승인 원본과 큰 장식·제목·워터마크용 변형 |
| 수치와 보드 | 실제 표시 크기, 불투명도, 상태 표현, 승인 보드 버전 |

공통 기준이 바뀌면 변경 항목과 적용 대상 화면을 기록하고 문서·보드·에셋의 버전을 함께 갱신한다. 한 화면의 임시 수정이 다른 화면의 표준으로 자동 확정되지 않게 한다.
